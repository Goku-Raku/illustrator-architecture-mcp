# 视觉语法：每个图形为什么存在

适用：已经知道要分析什么，但不知道信息如何变成元素，或一张图太满、颜色混乱、结论不清。分析维度见 [analysis-atlas.md](analysis-atlas.md)，实际绘图见 [mcp-execution.md](mcp-execution.md)。

## 1. 用关系选择元素

下表是图形语义词汇，所列元素不保证当前 MCP 有同名专用接口。可用原生路径、文字或可编辑 SVG 组合；应先查看工具能力。

| 要表达的信息 | 可以抽象成什么 | 图形构成与必要说明 | 不能偷换的含义 |
|---|---|---|---|
| 某处存在一个事件/设施 | 节点 | 点、环、符号或编号，锚定位置 | 点的大小默认无数量含义 |
| 可穿越/需授权/发生状态变化的位置 | 门槛 | 边界上的开口/短线/状态节点，必要时配时段 | 一般设施图标不能说明门当前是否开放 |
| 某类活动发生的范围 | 区域 | 填色、边界、标签；复杂区域可拆分 | 颜色相接不代表有直接通道 |
| 两对象应有关联 | 关系边 | 无箭头连线、矩阵单元或注释 | 关系线不是能穿墙的实际路线 |
| 人或物沿哪里移动 | 路径 | 连续折线/曲线、转折、实际入口、起终点 | 流线不是装饰波纹；平滑后不能切角穿墙 |
| 移动或作用方向 | 有向边 | 箭头与图例，起终点都可读 | 一个方向箭头不表示单向通行规定 |
| 高差/界面/管理造成阻断 | 边界或断点 | 线段、缺口、节点、局部放大 | 虚线仅在图例定义后表示推断、提案或隐藏之一 |
| 观察者朝向某目标 | 视线/视域 | 眼点、线或扇形、目标、遮挡说明 | 几何扇形不自动考虑遮挡，也不等于光照区 |
| 一个现象在连续范围变化 | 场 | 有坐标、单位、范围和数据的等值/网格/色带 | 透明渐变与毛刷密度不是计算结果 |
| 某对象在不同时间切换 | 状态序列 | 固定对象身份的分时小图、时间条、开闭矩阵 | 不同状态的图面颜色应保持同一类别含义 |
| 尺度、姿态和活动方式 | 使用者情景 | 人物尺度、姿态、家具/工具与动作范围 | 人物可作情景；无观察数据不能表示实际人次 |
| 结构、设备或新旧层次 | 系统分解 | 爆炸图、层编号、投影/对齐线、装配关系 | 爆炸位移是表达距离，非实际标高 |
| 局部机制决定总体结论 | 索引关系 | 总图编号/框选、局部图、对应标题 | 放大图不可悄悄换版本或与总图不对应 |
| 数据不足或关系不确定 | 不确定性 | 明确的未知标签、空白/纹理、来源短注 | 低透明度不能默认表示低置信度；未知不是没有 |
| 方案导致的增减 | 差异 | 同底图变更层、增/减类别、基准说明 | 提案不能混进现状成为“已存在”的证据 |

## 2. 分配视觉通道

先定义各通道的工作，再选美术风格。不是每张图都用全套。

| 通道 | 优先用来表达 | 使用条件与常见错误 |
|---|---|---|
| 位置 | 实际位置、相对关系、顺序 | 空间图中的位置通常已被建筑占用，不能再随意排列以暗示排序 |
| 形状 | 少量节点类别、状态 | 类别太多时形状难辨；用文字/编号补足，不堆图标 |
| 色相 | 离散功能、系统或使用群体 | 同类跨图同色；不让同一种红同时表示现状、危险和新增 |
| 明度/连续色带 | 有序等级或连续量 | 给出等级或数值范围；同一比较系列固定尺度 |
| 线宽 | 阅读层级，或有依据的数量 | 必须选择并说明一种含义；数量编码要给映射/图例，不能只为美观调整 |
| 大小/面积 | 有数据的数量，或层级 | 若圆面积编码数量，半径应按数量平方根变化；明确大小与何量对应 |
| 线型 | 不同状态、关系类别或证据状态 | 同图避免虚线同时表示地下、拟建和未知；另用标签拆开 |
| 纹理 | 类别补充、改造状态、未知范围 | 不必等同于材质；密度不应无意暗示数量；缩小后仍可辨 |
| 透明度 | 控制遮挡与背景层级 | 重叠会加深，容易形成假强度；图例说明重叠是否有意义 |
| 箭头 | 明确方向 | 引线、对齐线、尺寸线通常不需要箭头；过多箭头会把静态关联误画成流动 |
| 编号 | 跨视图对应、阶段、步骤 | 编号应能在文字和图上闭环；除非明确说明，不代表重要性排名 |

优先采用少而稳定的编码。颜色分群体后，可用线型分现状/提案，用文字标时段；再需要区分楼层时，常常拆成小图比追加形状、粗细、纹理更清楚。

图例中的样本必须与图上实际对象一致。若修改全局颜色后图例没变，图例会成为错误证据。可只列读者无法从位置/文字直接理解的编码，不强制每图都有大型图例。

## 3. 画面分层，不等于越淡越好

可按任务组织为：参考底图、选中对象、分析关系、证据标注、结论/图例。底图提供可核查的墙、门、标高、名称；即使降低对比，也不能淡到无法验证路径。

- **区域先服务辨认**：透明色块若盖住原有房间文字，先调整边界/透明度或移标签，不直接用白框抹去关键证据。
- **路径先服务连续性**：处理交叉时区分真实交汇与绘图跨越。用局部图、分时图或轻微错开配说明，不能为顺滑把真实路径挪出走廊。
- **节点先服务定位**：节点足以辨认即可；大小取决于输出尺寸，不按建筑真实尺度误画巨大圆圈。数量编码则另有图例。
- **文字先服务核查**：短结论靠近所解释关系；长来源可用编号索引。引线应指到准确对象，避免穿过多个候选对象。
- **人物、树、材质、照片有具体用途**：人物说明姿态/尺度/活动；树冠说明已知植被或明确提案；材料样本关联特定界面；照片证明现状。无相关信息时不添加。

没有统一适用于所有图幅的线宽、字级或透明度。先用一个代表性局部试样，在预期输出尺寸看门、墙、线与字是否仍清楚，再批量应用。同一套图维护一致关系，而非不分比例地复用同一个数值。

## 4. 选择构图结构

| 读者需要完成的任务 | 推荐组织 | 重点保留 |
|---|---|---|
| 在现场定位问题 | 主底图＋局部索引 | 方位/尺度按需要提供；边界与关键障碍 |
| 比较同一对象的状态 | 同尺度、同裁切的小倍图 | 对象身份、颜色含义、时段和未知一致 |
| 理解上下/里外关系 | 对应平面＋剖面，或清楚的剖透视 | 剖切位置、标高、活动姿态、界面与路径 |
| 理解系统分工 | 爆炸/分层＋系统编号 | 对齐线与原位参照；爆炸距离不当作几何证据 |
| 从现象导向改法 | 观察/证据图＋相应设计回应 | 用相同编号或位置让每项行动有对应发现 |
| 评估取舍 | 同条件方案图＋指标/定性比较 | 共同约束、单位/口径、代价和未知 |
| 解释多来源感知 | 地图定位＋照片/材料/观察片段 | 样本来源与采集范围，不把局部体验外推整体 |

不要把所有统计图压在地图上。只有数据与地理范围有精确对应时，图上图才有意义；否则独立统计图与定位地图并排更容易读。饼图罩在地图上，可能被误认成真实地理扇区。

## 5. 研究参考图时如何提取方法

逐张保留一条短记录：来源/访问状态 → 它回答的问题 → 可见的编码 → 依赖数据 → 可迁移机制 → 不可直接借用的部分。优先看关系是否成立、能否转成设计动作；避免只收藏配色与人物素材。

对优秀表达也保留批评：比例图的统计口径是否可知？大小和颜色是否在同时编码不同变量？视域有没有观察点？多个时段是否用相同底图？爆炸图有没有对齐关系？是否把形式变化假装成因果必然？

参考图可以启发新的元素类别，例如门槛、观察点、视域、活动姿态、支持设施节点、时段条、阶段边界、系统对齐线与原始观察样本。它们值得加入的理由是承载过去未表达的关系，不是填满空白。

以下结论来自实际查看公开图像的完整图面；Pin 正文受登录/403 限制，因此只陈述可见表达，不据标题推断原作者、项目性能或数据真实性。链接供追溯视觉来源，其数值和符号含义不自动适用于新项目。

| 可追溯图像 | 实际可见的组织 | 可迁移的方法与限制 |
|---|---|---|
| [分层功能与声音分析](https://www.pinterest.com/pin/7177680651049021/) | 楼层采用同底图的小倍图；声音用颜色分来源、圆大小分音量，斜线/实心分周期与持续，并设图例 | 各视觉通道各司其职；新项目只有具备声音数据与口径时，才可借用“大小=音量”编码，否则只画源的位置与类别 |
| [时间、活动与设计回应](https://www.pinterest.com/pin/277112183311646324/) | 日时间轴、分时段同底图点分布，与下方多种设计回应共同组织 | 从观察指向行动，用相同编号/位置联系发现与改法；有多少活动点必须来自观察或明确情境，不能为密度效果补点 |
| [多感官分析与样本](https://www.pinterest.com/pin/65231894598452192/) | 多个同底图与照片/材料样本关联；部分统计扇区覆盖地图 | 样本可补充地图难以表达的感受；统计比例与地理位置应分清，避免地图上的饼图被误读成真实范围 |
| [水系统轴测与剖面](https://www.pinterest.com/pin/474777985700521577/) | 上部沿系统追踪路线，下部剖面解释地下设施与湿地，编号对应文字 | 平面/轴测说明“经过哪里”，剖面说明“怎样工作”；水量、标高和系统效果仍须本项目输入 |
| [人物观察点与视线范围](https://it.pinterest.com/pin/carlo-scarpa-cultural-architecture-arch-architecture--328833210273759823/) | 多个人物眼点向中心目标展开灰色三角范围 | 视线需要观察者、目标与遮挡条件，不能用普通流线箭头代替；画扇形不等于完成视域计算 |
| [系统爆炸与对齐](https://za.pinterest.com/pin/4925880834495451/) | 外皮系统用突出色，其余骨架/楼层降为灰线，垂直虚线对应位置 | 强调一种系统同时保留原位关系；爆炸间距属于表达，不可作为真实层高或构造尺寸 |
| [功能与权限路径并列](https://www.pinterest.com/pin/108930884716286345/) | 同轴测分别表达功能与权限路径，并有控制点图例 | “是什么用途”与“谁能进入”是两层问题；分图更容易核查，控制点应绑定真实门与运营条件 |

这一组参考用于提炼表达机制，并不构成对 Pinterest 的穷尽研究或对所有项目都适用的规范。复用时仍应从当前设计问题和证据出发。

## 6. 成图检查

先遮住标题，图是否仍能让人认出对象、关键关系与状态？再只读标题，是否超过图中证据？检查缩小后纹理/点/虚线是否混成一团；去掉颜色后，关键类别是否仍有标签、形状或位置支持。没有原始可编辑文件或没有预期输出尺寸时，明确视觉核查的限制。

最后问：“哪项发现会让用户移动一个门、改一道边界、调整一个标高、换一组功能，或取消一个无效操作？”若没有答案，图可能仍停留在分类说明；回到当前设计问题判断是否有必要继续。
