# 从决策卡到 Illustrator：职责、能力与执行

仅在用户要求实际制图、改图或保存文件时进入执行。只问“如何分析”时，用本 skill 给图纸策划和设计操作建议即可。工具名称可能带服务器前缀，参数以当前连接的 schema 为准。

## Skill 与 MCP 分工

| 层 | 负责什么 | 不应承担什么 |
|---|---|---|
| Skill/模型判断 | 看图、提出问题、整理证据、选择抽象与编码、解释取舍、给设计动作 | 不把主观解释写成自动识别结果，不声称完成未执行的模拟 |
| 建筑 MCP | 渲染参考图、映射坐标、创建有语义的可编辑图形、检查/修改对象、读取配套方法资料 | 不判断项目真相，不从像素自动求房间、流量、气候或性能 |
| 原版 Illustrator 工具 | 打开/置入、通用图形、图层、字体、SVG、保存导出等实际可用能力 | 无专用接口时不能凭空假设可导入、自动避让或自动配准 |
| 外部专业数据/工具 | 测绘、路网、计算、气候、模拟、实测及可追溯统计 | 输入未核实前不能把参考图上的数值当本项目数据 |

拆出 skill 的收益是判断方法可独立建议、跨图纸复用，并按需加载；代价是方法与工具版本可能错位。因此技能文档保留能力边界，执行前读实际 schema；MCP 的只读 guidance 从同一份文档读取，避免另一套提示词悄悄漂移。这里没有强制购买、安装或调用其他软件的前提。

## 当前七个接口

| 工具/能力 | 现在用于什么 | 重要边界 |
|---|---|---|
| `arch_read_reference` | 实际渲染画板/局部，返回 PNG、`frame` 与 `expected_document` | 必须查看 PNG；对象清单不等于看过底图 |
| `arch_map_preview_points` | 把对应预览中的像素点换成画板 pt 坐标 | 只解决图形配准，不等于建筑米制尺度校准 |
| `arch_add_overlay` | 新图层中创建带语义的覆盖层 | 需准确文档身份、画板、唯一批次；不会理解或修复底图 |
| `arch_inspect_elements` | 读取图层/UUID、样式、几何和语义；缺少持久 ID 时会保留原备注并补写 UUID | 属于可能写入元数据的检查，不是严格只读；传入已确认的 `expected_document`，按实际叶子对象定位，不猜 UUID |
| `arch_style_elements` | 预检并批改允许的样式/语义字段，再读回 | 技术预检不是每次额外人工审批；遵守当前对象保护限制 |
| `arch_get_diagram_guidance` | 只读方法入口：原六主题及城市 `urban_site`、`urban_atlas`、`urban_example` | 返回与本 skill 相同的文档，不执行绘图；不需要打开 Illustrator |
| `arch_prepare_site_map` | 把明确声明的平面/投影坐标要素编译成 `overlay_params`，保持同一比例、方向和源 ID 对照 | 只读准备；不访问 Illustrator，不重投影、不算路网、不抓底图。返回结果经检查后再交给 `arch_add_overlay` |

旧版覆盖层五类：`zone` 区域、`route` 折线路径与箭头、`boundary` 边界、`label` 文字与引线、`hatch` 简单多边形内斜线。

本次覆盖层补充如下；若实际连接工具没有这些 `kind`，使用已存在的原生通用路径能力或先交付规划，不伪造参数：

| 新增能力 | 对应过去缺失的分析关系 | 关键参数/边界 |
|---|---|---|
| `marker` 节点标记 | 入口、观察点、冲突点、设备/支持节点、控制点 | `center`、`shape`、`size_pt`；形状为 circle/square/diamond/triangle/cross。标记没有内置建筑语义，靠 `role`/证据说明；大小不自动对应数量 |
| `smooth_route` 三次贝塞尔路线 | 弯曲移动路径、系统连接、概念作用路径 | `start` 与 `segments`；每段显式提供 `control1`、`control2`、`end`，均为绝对画板坐标。不是自动寻路/自动平滑；复核曲线是否越界切角 |
| `sector` 几何扇形 | 视线方向范围、角度示意、具有明确来源的作用范围 | `center`、`radius_pt`、`start_degrees`、`end_degrees`；0°向右、正角度顺时针。不会避开遮挡，不计算视域、等时圈或性能；圆弧是贝塞尔近似 |
| `compound_zone` 带洞区域（v3） | 城市图底中的中庭、环形地块、带内岛水面、排除区 | `outer`、`holes`、`fill`、可选 `stroke`；原生复合路径，真实透明洞。外环/孔洞不含重复终点，洞须严格在内且互不接触、相交或嵌套；不做布尔求交 |
| 证据与来源字段 | 从图形对象追到当前依据 | `evidence_kind`、`source_ref`、`data_ref`；四种证据类型 observed/inferred/proposed/supplied。引用只存文本，不自动抓取/验证；`evidence` 继续保存解释 |

以上是工具契约，不代表已在用户当前图稿完成绘制或验证。语义批改针对读取命中的叶子对象；父组仍可能保留创建时记录，不要把一片叶子的修改说成全组同步更新。

## 从图纸任务到执行批次

1. **明确可修改范围与成图目的。** 沿用授权，读取当前文档/画板/图层。用户只要局部调整时，不为套方法重画全板。
2. **实际看图。** 用 `arch_read_reference` 检查整体，必要时看决定结论的局部；保存 `frame` 与 `expected_document`。对关键门洞、文字、边界不清的区域保留未知。
3. **准备简短决策卡与元素表。** 为每类元素说明承担的关系、依据、图形类型与编码。问题无法支持的量化字段不填；`confidence` 可省略，不能用任意小数替代证据。
4. **对准坐标。** 用本次返回 PNG 的原始像素尺寸取点，用对应 `frame` 换算。底图移动/缩放、画板或裁切变化后重新读取。真实比例尺需独立可靠尺度。
5. **组织可编辑覆盖层。** 区域/关系/标签按阅读层级排序；`arch_add_overlay` 中较后的元素在上方。按当前 font schema 使用实际安装字体。若需独立图层和批次，用语义清晰的名称，避免把项目全部内容装进一个无法定位的大批。
6. **检查并细调。** 读取返回 UUID、组件与语义，再用 `arch_style_elements` 预检。预检结果正确且任务已授权时直接执行；失败先修对象范围或参数。不要反复让用户批准普通样式微调。
7. **回到图纸验证。** 重新查看预览，检查对位、曲线穿越、关闭边界、引线指向、颜色/图例和文字；同状态/同方案系列保持共同编码。结构化读回可验证字段，实际预览可验证阅读，两者不能互代。
8. **按需求交付。** 用可用的原版工具保存 AI/导出；报告实际完成、验证范围与关键未知。未实际保存时不要说“已保存”。

元素表可很短：

| 语义 ID/role | 几何依据 | 内容依据 | 图形/编码 | 当前状态 |
|---|---|---|---|---|
| gate.d1 / 夜间关闭界面 | 首层 v1 已知门位置 | 运营表 v1 的 20:00 规则 | marker＋短注 | supplied；门位置若未核实需说明 |
| route.night / 夜间到达候选 | 候选通道提案 | 独立运营目标 | route 或 smooth_route，提案线型 | proposed；不表示现状存在 |
| view.a / 观察方向 | 观察点与目标位置 | 可视联系假设 | sector＋眼点/目标 | inferred；几何示意未做遮挡计算 |

一组对象混用不同依据时，在各元素 `evidence` 中说明，不能仅给整张图一个“observed”总标签。`source_ref` 可以是来源 URL/文件/图号，`data_ref` 可以是表格行列/数据集标识及有关时间/单位。

## 哪些画面现在可组合，哪些尚需补

| 需求 | 当前做法 | 尚不具备/需要谨慎 |
|---|---|---|
| 入口、控制点、冲突/观察节点 | marker＋label，必要时配 boundary/route | 无自动节点识别，无项目图标语义推断 |
| 曲线路径与方向 | smooth_route 显式控制点，箭头依端部切线定向 | 不会自动避墙、路网寻径或判断是否可通行 |
| 视线/范围示意 | marker＋sector/route＋边界与注释 | 无遮挡求交/isovist、地形视域或等时圈计算 |
| 时间轴、矩阵、分时小图 | 使用通用原生图形/文字及复制布局能力，按来源手动组织 | 无专用时序模型、自动场景切换或运营求解器；先确认通用工具 |
| 图例、比例尺、北针 | 用有依据的值/方向组合元素，或用户已有图例 | 无自动比例校准或北向判断；图例要随实际编码更新 |
| 带中庭洞的区域 | `compound_zone` 的外环和孔洞；也可从平面地图 Polygon 内环编译 | `zone` 与 `hatch` 仍不支持洞；复合路径及其成员不进入 `arch_style_elements` 批改，需核查通用工具能力或重建明确的新版本 |
| 城市图底、道路和设施叠图 | `arch_prepare_site_map` 统一变换 Polygon/MultiPolygon、LineString/MultiLineString、Point/MultiPoint；再创建覆盖层 | 不接收经纬度坐标、不转换 CRS、不修 GIS 拓扑、不自动按属性分类或简化大数据 |
| 剖透视、爆炸图 | 从已有准确底图叠加系统和关系；需要时导入外部生成的几何 | MCP 不从平面自动生成准确三维，不自动求投影或切剖 |
| 人物、家具、植物、材料样本 | 使用具有尺度/用途依据的可编辑现有素材/图形 | 无自动“填满画面”素材生成；数量与姿态不能冒充调查 |
| 定量密度/环境/数量图 | 输入经过核对的数据与统一图例，用适当绘图能力呈现 | 无自动人流、声学、日照、CFD 或碳核算引擎 |
| 标签避让和复杂排版 | 预览后检查，再调整文字/引线位置 | 无自动碰撞检测/避让；中文排版须实看 |

后续扩展优先级应由重复任务和实际失败决定。带来源的图例、时段/状态数据模型、可复用同底图场景、标签碰撞提示等仍是候选需求，不是本版已完成能力。

## 城市矢量底图的准备

先从 [城市流程](urban-site-analysis.md) 选择证据与图层；需要 GIS 分析时先在具备相应能力的工具中完成。`arch_prepare_site_map` 只负责可靠搬运明确的几何。

1. 输入为 GeoJSON 形状的 `FeatureCollection`，但坐标必须是已投影的米/英尺/毫米，或具名的本地平面坐标。这不是将默认 WGS84 经度纬度的 RFC 7946 文件直接当米；没有重投影功能。显式写 `source_coordinates:{kind,crs,units,y_axis}` 和 `source_ref`。
2. 每个 feature 需唯一的字符串或数值 `id`；字符串 `"1"` 与数字 `1` 不同。Polygon/MultiPolygon 环必须显式闭合，孔洞按内环保留。仅支持二维，不接收 null geometry、GeometryCollection、Z/M 或自动修复的几何。
3. 用 `default_style` 或 `feature_styles` 明确每个要素的角色、填色/描边、点形与证据。覆盖样式是完整替换，不是合并；`properties` 不用于自动分类、不作为指令执行，也不原样复制。图例和分类断点由经过核对的分析决定。
4. 系列图使用共同 `source_extent:[xmin,ymin,xmax,ymax]` 与同尺寸 `frame:{left,top,width,height}`。工具等比居中，按声明的 Y 方向翻转；不会拉伸塞满、裁剪、忽略超界数据。单点/水平线等零面积边界需显式给正宽高 extent。
5. 检查 `calibration.actual_frame`、`scale_pt_per_source_unit`、`feature_mapping` 与 warnings。`nominal_scale_denominator` 仅来自声明单位与纸面 pt；不校正投影变形、不证明测量精度。不能用其推断真北或忽略导出后的缩放。
6. 检查 `overlay_params` 再提交 `arch_add_overlay`。准备成功不代表已生成 AI 对象，也不验证文档身份；创建时仍须实时文档核对。按返回的源 ID → 语义 ID → 创建对象 UUID 链追溯。

上限：200 个源 feature、20000 个源坐标（含闭环终点）；多几何展开后仍不能超过 200 个覆盖元素，另受覆盖层顶点/原生对象上限。超限时先按共同 extent 分批或在外部有依据地简化，不能静默截断。图形标记尺寸与描边采用纸面 pt，可能超出 frame；frame 约束的是几何坐标，不是完整可见边界。

路径图层不隐含连接：桥下与桥上、隔墙近邻、私有路、夜间关闭入口，仍由拓扑、时段与通行资格证据决定。MCP 不把插入的线算成步行等时圈。

## 失败与边界

`outcome_unknown:true` 或原生/通信异常时，先恢复连接并核对 `expected_document`，再检查目标图层、批次或 `target_uuids` 的实际状态。覆盖层用唯一 `batch_id` 定位；样式写入用返回的目标 UUID 逐个读回，不把未知结果当作无修改或已回滚。不要盲目重试，不进行固定次数全局撤销。收到 Illustrator 的具体错误结果时，按 `partial`、`changed`、`rollback_complete` 等实际字段处理；以工具返回和复查确认回滚。

样式预检的通信失败也会返回 `outcome_unknown:true`，但 `dry_run:true` 与 `changes_possible:false` 表明该预检不会写样式或备注；它仍不等于预检成功，不能直接跳到 apply。实际写入中断的 `changes_possible:true` 表示目标可能已部分修改。检查工具自身可能补写 UUID，恢复时应明确文档和目标范围。

斜线中心线裁剪仍可能在边缘溢出半个线宽；分组件透明度的重叠可能加深。路径/填充只是可编辑几何；严格的证据、正确的抽象与再看一遍实际图面，仍然由整个工作流程完成。
