# 第二轮升级：把分析判断与绘图执行接起来

版本：`1.10.3-architecture.2`。本地独立副本，不是上游正式发布。

## 相比上一版补了什么

上一版解决的是固定底图上的五种覆盖元素，以及预览坐标、样式和失败恢复。本轮把“值得分析什么、如何抽象、图能证明什么”补成配套方法，再补最常用的几何缺口。研究记录见 [Pinterest 图例研究](PINTEREST-RESEARCH.zh-CN.md)，方法正文见 [分析图方法论](DIAGRAM-METHODOLOGY.zh-CN.md)。

| 表达需求 | 上一版 | 本轮处理 | 实际边界 |
|---|---|---|---|
| 入口、门禁、停留、冲突、采样节点 | 要手写多边形 | `marker`：圆、方、菱形、三角、十字 | 符号本身不判断真实入口或门禁 |
| 有弯曲和切向的流线 | 折线；需跳转原版路径工具 | `smooth_route`：原生三次贝塞尔与端箭头 | 用户/模型给控制点，不自动绕墙或找路 |
| 视线、范围、扇区 | 手算多边形近似 | `sector`：原生曲线边界的扇形/圆盘 | 不计算遮挡、可视域、噪声或风场 |
| 事实/推断/设计意图的区别 | 自由文本 evidence | 新增 `evidence_kind` 枚举；保留 evidence | 不是自动可信度判断 |
| 证据来源与数据口径 | 混在自由文本 | `source_ref`、`data_ref`；样式微调可补写并读回 | 仅存引用，不自动访问/验证链接 |
| 分析维度和抽象选择 | 简短四类图表 | 可安装 `architecture-diagramming` skill | 不强制所有项目做同一图单 |
| MCP 无 skill 环境的指导入口 | 无 | 只读 `arch_get_diagram_guidance` 六主题 | 读取同一套文件，避免两份方法漂移 |
| 分时段/人群/方案对比 | 手工组合 | skill 给同范围小倍图、共享图例和控制变量规则 | 尚无专用批量小倍图生成接口 |
| 系统循环与依赖关系 | 一般箭头 | 节点+边+介质+方向的组合方法 | 尚无自动图布局或流量守恒求解 |
| 剖面、分解轴测、视点序列 | 一般矢量覆盖 | 给剖切依据、注册线、层序和视点对照规则 | 真实几何先在 Rhino/来源图纸生成 |
| 面积/强度/流量的定量编码 | 无判断流程 | 区分名义、序数、数值；说明面积、半径、线宽映射 | 不从无比例的截图虚构数值 |
| 人物、家具、植被与材料 | 通用图形/置图 | 依分析目的选姿态、尺度、冠幅、界面或图样 | 未内置庞大剪影素材库；可用现有 symbol/SVG |
| 标签避让、开洞填充、蒙版场 | 部分手工 | 明确组合方案与外部几何边界 | 未实现自动标签避让或带洞区域布尔运算 |

## 为什么分成 MCP 与一个 skill

MCP 对坐标、几何、属性和回读承担确定性责任；skill 对分析目标、证据、图种与设计动作给出决策准则。这能让同一组图形用于不同建筑问题，同时让研究方法在没有 Illustrator 时仍能指导分析。

不将每一种分析图注册为单独工具：日夜对比、运营状态、生态循环的组合很多，独立工具会迅速重复颜色、文字、节点和错误处理。先增加三个高复用的原语，其他用已有对象组合。以后若真实任务反复出现相同可靠流程，再把它提升为专用接口。

也不把审美判断硬编码为“绿色=生态、红色=冲突、每图必须有北针”。图例和项目已有语义优先；示意关系网络不需要地理北向，未知状态必须区别于零值。

## 最小使用例

```text
用 architecture-diagramming 分析这张首层底图。
先找出值得检验的空间关系，给出证据、图种、编码和设计动作。
选对当前方案最有价值的图，在 Illustrator 里生成可编辑分析层。
缺失的时间/人数/北向不要猜；完成后查看真实预览。
```

也可以仅问“我可以从哪些方面分析这个设计”，skill 会停在建议层，不自动绘图。

六个指导主题：`overview` / `workflow` / `analysis_atlas` / `visual_encoding` / `worked_examples` / `mcp_execution`。只读需要的一篇。

## 新几何调用约定

所有点仍为指定画板左上角起算的 pt、Y 向下。保留 `expected_document`、`batch_id`、独立图层、批次去重和回滚机制。三个新类型嵌入原来的 `arch_add_overlay.elements`：

```json
[
  {"kind":"marker","id":"entry-a","role":"proposed_entry","evidence_kind":"proposed","evidence":"示例，非真实项目","center":[80,120],"shape":"triangle","size_pt":12,"rotation_degrees":90,"fill":"#206C72"},
  {"kind":"smooth_route","id":"route-a","role":"proposed_route","start":[80,120],"segments":[{"control1":[140,120],"control2":[120,200],"end":[200,200]}],"stroke":{"color":"#206C72","width_pt":2},"arrow":"end"},
  {"kind":"sector","id":"view-a","role":"view_direction_sketch","center":[300,150],"radius_pt":70,"start_degrees":-35,"end_degrees":35,"fill":"#D3A65C","opacity":25}
]
```

圆形符号用 `size_pt` 表示直径；十字为封闭加号。`rotation_degrees` 顺时针。扇形 0° 向右、正角顺时针，扫角等于 end−start；跨 0 的顺时针 20° 用 350→370。360° 为无径向接缝圆盘。圆弧是常用三次贝塞尔近似，不能用作测绘精度圆弧。

`smooth_route` 的控制点是绝对画板坐标。端箭头沿曲线端切向；相邻段不自动保证光滑连接。扇形没有障碍物裁切，画面必须自己核对墙体/遮挡。

来源字段可以在创建时写入，也可通过 `arch_style_elements.edits[].style.semantic` 补写到明确的叶子 UUID。语义组保留初始说明，修改叶子不会自动同步整组及其他部件。

## 验收

检查真实预览与对象结构，并区分软件正确和建筑判断正确：曲线控制柄能读回，不等于路径可达；扇形能画出，不等于该范围实际可见。实际执行结果、测试数量和本机验证范围单独记录在 [VALIDATION-V2.md](../VALIDATION-V2.md)。
